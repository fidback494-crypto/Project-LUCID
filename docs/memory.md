# 기억 구조

## 한 턴 안의 기억

- `ConversationManager`: 최근 10개 메시지를 프로세스 메모리에 보관한다. 실행을 다시 시작하면 이 짧은 버퍼는 초기화된다.
- `WorkingMemory`: 최근 관찰과 반성 기록을 최대 20개까지 보관한다. CognitiveEngine에는 그중 일부만 들어간다.
- SQLite 장기 기억: 사용자의 명시적 사실, 대화 에피소드, 내적 경험, 자율 목표를 저장한다.

## 검색과 전달

각 사용자 입력에서 `MemoryExtractor`가 저장 가능한 사실을 추출한다. `MemorySearch`는 단어와 정규화된 키워드로 활성 장기 기억을 최대 5개 찾는다. 대화 에피소드는 관련 기록 최대 3개, 내적 경험도 최대 3개를 검색하지만 현재 CognitiveEngine 프롬프트에는 각 목록의 첫 항목만 전달한다. 대화 검색 범위는 `MIN_CONVERSATION_MEMORY_YEARS`(현재 5년)로 제한된다.

프롬프트에는 관련 사용자 기억 일부, 최근 작업 기억, 마지막 연락 시각 및 간격에 맞춘 안내를 넣는다. 검색은 의미 임베딩이 아니라 SQLite 텍스트·키워드 일치 방식이다.

## 보존과 삭제

DB 기본 위치는 `data/lucid_memory.db`이며 `LUCID_DATA_DIR`로 바꿀 수 있다. 장기 기억 저장은 사용자별 사실을 대화 예시에 굳혀 넣지 않도록 대화 습관 학습 데이터와 분리한다. 기존 DB 마이그레이션, 활성 기억, 삭제 이력의 자세한 스키마는 `LongTermMemory` 구현을 기준으로 한다.

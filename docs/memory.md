# 기억 구조

## 캐릭터 설정과 관계 경험의 세 단계

1. **핵심 설정**: 이름, 꿈에서 태어난 존재라는 점, 꿈을 먹고 생존하는 점, 기본 성격과 말투를 매 대화에 짧게 전달한다.
2. **상세 설정**: 꿈의 세계, 능력, 과거, 기억의 비밀, 외형 등은 `Identity.relevant_detailed_settings()`가 현재 입력의 키워드와 맞는 항목만 골라 전달한다. 기억의 회랑은 `lucid/persona/WORLD_MEMORY_ARCHIVE.md`, 최종 외형은 `lucid/persona/CHARACTER_FINAL_APPEARANCE.md`에서 읽는다. 회랑의 최종 비밀만 미확정으로 유지한다.
3. **경험과 관계**: 대화 에피소드와 명시적으로 알려 준 사용자 사실은 SQLite에 저장한다. 관련 에피소드 최대 3건을 검색하고 그중 최근접 2건을 인지 프롬프트에 전달한다. 에피소드 전체는 기록되지만 약속이나 사건을 별도 구조화해 추출하는 기능은 아직 없다.

## 한 턴 안의 기억

- `ConversationManager`: 최근 10개 메시지를 프로세스 메모리에 보관한다. 실행을 다시 시작하면 이 짧은 버퍼는 초기화된다.
- `WorkingMemory`: 최근 관찰과 반성 기록을 최대 20개까지 보관한다. CognitiveEngine에는 그중 일부만 들어간다.
- SQLite 장기 기억: 사용자의 명시적 사실, 대화 에피소드, 내적 경험, 자율 목표를 저장한다.

## 검색과 전달

각 턴에서 `MemoryExtractor`가 명시적 사실을 추출하고 `MemorySearch`가 활성 사실을 검색한다. 모델에는 최근 작업 기억, 관련된 최근 대화 원문 최대 2건, 내적 경험 최대 1건, 마지막 연락 시각, 과거 세션 요약 최대 2건을 보낸다. 세션 요약은 검색어 일치 수와 최근 시각 순으로 고른다.

## 오래된 대화 묶기

기동 시와 사용 중의 정기 점검에서 7일이 지난 대화를 처리한다. 두 턴 사이에 30분 넘는 공백이 있거나 한 묶음이 50턴에 이르면 다음 세션을 시작한다. 결정, 요구사항, 선호, 남은 작업을 나타내는 표현과 시작·마지막 발화를 골라 최대 850자의 요약을 만든다. 시작·종료 시각, 요약, 검색용 단어, zlib로 압축한 전체 원문을 같은 SQLite 파일에 저장한다. 세션 기록과 원본 행의 이동은 한 트랜잭션으로 처리한다.

`/memory sessions [검색어]`는 세션 번호와 요약을 보여 준다. `/memory session <번호>`는 해당 세션을 풀어 발화 원문과 시각을 보여 준다. 최근 대화와 사용자 사실·변경 이력은 각각 기존 테이블에서 관리한다.

## 보존과 삭제

DB 기본 위치는 `data/lucid_memory.db`이며 `LUCID_DATA_DIR`로 바꿀 수 있다. 장기 기억 저장은 사용자별 사실을 대화 예시에 굳혀 넣지 않도록 대화 습관 학습 데이터와 분리한다. 기존 DB 마이그레이션, 활성 기억, 삭제 이력의 자세한 스키마는 `LongTermMemory` 구현을 기준으로 한다.
